# 猫咪照片理解、迭代评审与数据准备

本设计面向“Codex 看获准参考图 → 识别差异及不确定项 → 提出有限修改 → 本地执行 → 看实际渲染 → 决定保留/回退/停止”的工作方式。脚本负责受控执行和可重现证据，视觉理解负责解释图像与提出假设；二者都不能代替主人确认猫的熟悉感或证明未观察到的三维结构。本文不增加现有 CLI/Skill/严格 contracts 的未知字段，不重写造型室，不启动训练、下载模型或调用外部服务。

默认参考图、原模型与渲染留在用户本机。云端缺图、缺私有母模、缺 Blender 或工具版本不匹配时，输出待补证据/本地任务，状态保持 blocked，不能用 fixture、图片描述或曾经成功的脚本冒充本轮真实视觉结果。

运行在 Mac 的 Codex Agent 若仍将图像提交云端模型，也属于外部处理，不因“本地运行客户端”而自动获准。默认使用获准的本机推理或人工标注；外部观察器须先确认原图/裁切/渲染/特征的传输范围及留存/用途条款。未配置本地视觉模型时，保留 unavailable，不用规则遮罩冒充猫专用照片理解。

## 先区分观察、推测与可操作范围

照片中看到的是某个视角、姿态和光照下的投影。正面看起来脸宽，可能来自头颅、颊毛、焦距或低头；看起来眼睛大，可能来自眼睑张开、瞳孔扩张、近距离镜头或透视。不能把单图视觉描述直接转换为唯一真实的三维参数。

每条观察至少记录：本地图片引用及摘要、可见区域、视角/姿态、质量与遮挡、实际图像依据、可能的混淆来源、支持/反驳它的其他视图、对应现有控制或 unsupported、建议修改幅度与验证视图。置信度是经校准的可用性描述，不能把模型随口给的 0.9 当作 90% 的客观正确率。没有可见依据时使用 unknown，不填猜测的尺寸/毛向；品种标签不替代个体观察。

观察分成三层：

- **可见事实**：例如“这张正面照片左眼被遮挡”“白色区域延伸到鼻梁”“所选侧面图口鼻轮廓比当前渲染更突出”。应能指向图中区域。
- **待验证假设**：例如“需要增加口鼻前后深度”“头部显宽主要来自毛层”。至少通过另一视角、灰模/仅原模型对照或有限参数敏感性渲染验证。
- **不可由现有证据确定**：隐蔽身体表面、真实毛囊密度、绝对体重/长度、遗传颜色、完整三维背面花纹、原生 groom 曲线和动画绑定。不能以“视觉模型认识猫”跨越这些缺口。

## 特征到现有系统的能力表

依据 `lib/cat-creator-design.ts`：当前 20 项 shape 为 14 项面部控制与 head/ruff/body 各自的毛量和毛长；全部范围 0–100，`headRound + headWedge <= 100`。它们不是毫米或品种百分比。`cat-coat-profiles.ts` 将 short/long 映射到同一 Norwegian 基础、hairless 映射到 Sphynx；相同滑块在不同底模上不表示相同绝对结构。

| 特征 | 图像可支持的观察 | 主要不确定性/混淆 | 当前可用操作 |
| --- | --- | --- | --- |
| 脸形与颅颊轮廓 | 多视图中的脸宽/脸长比例、颊部/下颌外轮廓 | 毛体积、头部俯仰、透视、左右遮挡；单正面不能确定深度 | `headRound`、`headWedge`、`headWidth`、`headDepth`、`cheeks`、`jaw`；先固定毛层观察 |
| 口鼻 | 对齐侧面/斜面中的口鼻突出、胡须垫宽、鼻梁转折 | 白毛/阴影边界不能当几何；镜头近大远小 | `muzzle`、`muzzleWidth`、`noseBridge`；轮廓与正面共同验收 |
| 眼区 | 双眼可见时的间距、眼裂倾角、相对大小和包覆关系 | 眼睑/眨眼、瞳孔、凝视、角膜高光；眼球尺寸不等于眼裂高度 | `eyeSize`、`eyeSpacing`、`eyeTilt`；需验证 Blink 与眼睑联动。当前无虹膜色/瞳孔控制 |
| 耳朵 | 耳尖相对头部大小、可见外张与对称性 | 警觉/转耳姿态、背侧遮挡，毛束不等于耳廓 | `earSize`、`earTilt`；当前无独立耳根位置或每耳控制 |
| 身体与比例 | 完整站立多视图的长宽比例、背线、腿/尾轮廓 | 趴卧、镜头高度、肥瘦与长毛不可分，缺尺度物无法估绝对大小 | **当前 creator v5 无**体重、躯干长、腿长、尾长等控制；记录 unsupported，不能把头宽当身体参数 |
| 毛色、白斑、条纹、重点色 | 可见表面的色块边界、局部条纹与左右差异 | 白平衡、曝光、阴影、年龄/季节；看不见背腹花纹 | **当前 creator v5 无** pigment/pattern 参数。现有 `cat-coat-pattern.ts` 属于旧 CatDesign 路径，不能直接套到当前母模 |
| 毛长与毛量外观 | 毛束轮廓、耳毛/颈鬃相对长短、可见稀密趋势 | 逆光、梳理、压毛、湿毛、季节；视觉覆盖不等于真实毛囊密度 | `headFurLength/Density`、`ruffFurLength/Density`、`bodyFurLength/Density`；只有 groom 模式且真实能力支持时有效 |
| 毛流方向与层次 | 可见毛束的大体走向、分缕、下垂及逆向异常 | 纹理条纹不是毛向；内层/背面不可见 | 当前六项毛参**没有**局部方向控制。方向/束化来自 groom/profile 实现；先标注差异，不为一只猫直接更改所有猫共用 profile |

`coatMode:source` 不支持完整程序毛的实时毛长/密度拟合；hairless 不应凭图像需求强行植入 Norwegian groom。不可操作项与证据不足项分别报告，不能虚构 CLI 参数、morph 或模型权重来满足观察。

## 一轮评审怎样执行

1. **建立基线。** 对获准模型固定 `modelRevision`、模板/拓扑/groom 版本、appearance、全部贴图摘要、工具版本与渲染 scenario。原模型只读，输出进入新隔离目录。核对实际 morph、bodySurface/primitive、蒙皮和材质；不能只有 manifest 声称存在。
2. **先对齐相机与姿态。** 按参考图的头部朝向、视高、透视或正交类型及可见标志估计相机；先检查瞳孔中心、鼻尖、耳根、下巴等可见标志重投影。如果需要更改相机才能对齐，就先完成相机校准，随后冻结，不能每次改几何又自由移动相机来“变得更像”。侧面和斜面也各保留固定相机。
3. **Codex 作有依据的评审。** 同时看参考、基线实渲染和必要的灰模/仅原模型/完整 groom 对照，列出少量按影响排序的差异，明确 unknown 和 unsupported。区分身份特征（主人能认出的花纹/脸型）、解剖合理性、渲染风格和工程缺陷。
4. **提出有限候选。** 一次优先只改一个有能力支持且有证据的参数，初始最大改动例如 3 个滑块单位。记录旧值、新值、理由、预期改善区域和可能退化视图；这是保守实验策略，不是已证明的最佳步长。其它参数、毛量、纹理、光照、相机、随机种子保持不变。
5. **本地运行并返回实际证据。** 经现有严格 request/appearance 与能力校验后执行允许的固定操作，输出新的模型/参数、固定视图图像、日志和校验报告。若 renderer 不支持某参数或输出缺失，本轮无有效候选；不把请求成功当作几何变化发生。
6. **再看图决定。** 评审 baseline/candidate，必要时隐藏候选标签以减少“新的一定更好”的偏见。检查目标视图改善是否超过噪声、保留视图是否退化、结构门槛是否通过。保留仅意味着下一轮的本地实验基线，不意味着主人确认、生产验收或发布批准；否则回退至上一确定基线并保留失败证据。

建议的运行记录放在现有 job/被忽略的本地 artifacts 下，包含 baseline 与 candidate 摘要、允许改动、实际 diff、固定 scenario、观察依据、模型/人工意见和决定。它是评审记录，不向已有严格 schema 塞入未定义字段，也不写入真实宠物回忆或账户资料。现有 contracts/CLI/Skill 继续承担输入、文件、资源和发布边界。

## 不把“更像”压成一个总分

| 评价轴 | 可使用的证据 | 失败时的处理 |
| --- | --- | --- |
| 个体熟悉感 | 主人对对齐视图的盲比较、明确指出脸型/花纹/表情依据 | 记录偏好与不确定，不让通用视觉模型代替主人认可 |
| 解剖与轮廓 | 可见标志重投影、按尺度归一化的轮廓差、正/侧/斜面人工评审 | 跨视图冲突时暂停单图拟合；不得靠换视角藏缺陷 |
| 毛色/材质 | 经曝光/色彩处理记录的可见区域、色块边界、材质中性光下对照 | 不将目标光照烘焙成贴图，不靠增加亮度掩盖几何差异 |
| 毛发外观 | 头/胸/体覆盖、轮廓、毛向与分缕、耳毛/胡须、近远景和动作图 | 明确密度/毛长/光学各自影响，不把减少毛层当作解决碎毛 |
| 结构与动作 | 实际 GLB 解码、拓扑/morph/skin 布局、权重、闭眼、毛根漂移与关节穿插 | 任一必需检查失败即不接受候选，视觉评分再高也不放行 |
| 稳定性与资源 | 同输入同版本可重现、无意外文件变更、受限内存/时间、加载/导出回读 | 保留失败任务，回到上一基线，不重置数据或扩大资源绕过问题 |

像素 MAE、SSIM、轮廓 IoU、CLIP/DINO 类相似度可作为诊断辅助，但不能单独判定“就是这只猫”。它们可能奖励相同背景、姿态或毛色，也可能惩罚正确形体下的光照差异。只有可见且对齐的区域参与对应测量；不以不可见区域为零误差、不因模糊而奖励候选。身份、解剖、材质、groom 和结构分别保留结果，结构 gates 不参与加权抵消。

## 保留视图与停止条件

至少保留一个没有用于选择参数、调步长或提示视觉评审的视图/拍摄 session。拟合结束再看保留视图；一旦根据它继续调整，它就变成开发视图，需要新的最终保留数据。来自同张照片的裁切/翻转、近似连拍、同一截图不同分辨率不算独立保留视图。数据允许时保留另一侧或不同光照 session，而不只反复使用同一标准正面。

每个实验先写好预算与停止条件；首个试验可设最多 3 次修改/渲染、每次一个参数、每步绝对变化不超过 3，任一时刻可回退。以下情况必须停止而不是无限调用模型：

- 缺有效参考、资产/授权、渲染证据或相机仍无法对齐；观察为 unknown 或目标超出已有控制能力。
- 任一模型/参数/绑定/资源 gate 失败；闭眼、蒙皮、毛根或导出回读出现退化；任务超时/输出不完整。
- 连续两轮没有超过重复渲染噪声的改善，或参数在两值间来回振荡；必须报告无收益而非累积“优化次数”。
- 训练/拟合视图改善但保留视图或另一个关键部位明显退化；需要重新分析混淆原因，不能只保留好看的截图。
- 达到事先设定的误差/人工偏好目标或轮数预算；交付最好候选、剩余差异和主人待确认项。

结构 gates 至少包含：输入/版本/实际文件摘要一致；坐标与单位；显式 bodySurface；有限坐标、正确索引与 accessor、合理拓扑/UV；morph 名称和位移确实生效；骨架层级/权重与面部联动；动画与静态 groom 的表示边界；实际内存/时间预算；原始源文件未改。私有资产未运行的项目保留 blocked/unrun；已有 synthetic fixture 通过不能替代。

## 数据集：先保存可复现的真实试验，再谈训练

最有价值的早期数据不是大量无上下文猫图，而是**同一个体、多视图参考、明确参数版本、成对候选渲染、实际三维变化和人类取舍**。一只猫就可验证工作流，但不能据此宣称形成可训练猫专用模型的数据规模。

建议每个本地样本组保存下列内容；未来若需要机器可读格式，应通过现有契约的版本化扩展审查后加入，而不是临时放宽严格解析：

- 个体匿名 ID、拍摄 session、授权引用与允许用途；原图摘要、处理版本、视角/遮挡/清晰度及尺度证据。参考图可以只作审查，不默认允许训练。
- 同个体尽可能一致姿态的正/侧/斜面、身体图与必要细节；有拍摄条件时保存标定与中性光。主人说明的关键识别点与其原话分离，不把模型推测写成事实。
- 确切母模/拓扑/UV/groom/工具版本与基线参数，所有 candidate 参数 delta；真实导出模型与贴图/groom 摘要；已运行的结构检查和失败/回退记录。
- 与参数成对的固定相机、多视图渲染；可见 landmark、分割轮廓、局部材质/毛向标注及标注来源。渲染参数不是照片中真实结构的 ground truth，只是该渲染的已知生成条件。
- 对随机顺序 A/B 候选的人工评分与理由：主人熟悉感、三维美术/解剖、毛发/材质、结构可用性分别记录；允许相同、无法判断、两者都不对。少量复评用于衡量评分稳定性。
- 个体级训练/开发/测试划分和真正未参与拟合的保留视图；记录同猫多年龄、重复图片、翻转裁切等关联，避免信息泄漏。最终评测还应有未见品类/毛型与失败案例，但不能因数量不足编造样本。

### 按模块补齐的训练证据

| 目标 | 现成工具可先承担 | 真正需要猫专用数据的部分 |
| --- | --- | --- |
| A：形态参数建议 | 多模态模型描述差异、通用分割/landmark 提议、受约束参数搜索 | 同拓扑参数和多视图照片/实渲染配对、猫眼睑/口鼻/耳朵结构、姿态/毛体积解耦、跨个体泛化与置信度校准 |
| B：毛色/花纹 | 可见区域分割、色块/边界比对、局部标注建议 | 标定色彩、稳定 UV、跨视图对应、不可见表面处理、花纹连续性；照片光照与 albedo 分离，使用权完整的配对纹理 |
| C：毛长/毛流/密度 | 识别明显轮廓差异、可见毛向标注、现有 groom 的确定性调参 | 真实表面锚定、引导曲线/方向场、长度尺度、下绒/护毛、动作与光照下表现；普通手机单图不足以给出真实密度监督 |
| 渲染评审/修改排序 | 通用视觉模型给出差异描述与候选排序，规则约束动作 | 同猫候选的人工偏好、多视图退化/结构失败标签、校准与对抗背景/光照混淆，不能只训练“看起来漂亮”的总分 |

先建立零训练基线，量化在现有控制范围内能改善什么、失败在哪里；只有误差主要来自预测而非母模能力缺失、数据与许可足够且另获授权时，再讨论训练预算。不得用优化 prompt 或执行脚本的次数冒充训练迭代。

## 可考虑的现成视觉组件及边界

下表是可替换能力类别与候选，不代表本项目已安装、调用、核实当前许可证或承诺准确率。本设计未发起外部查询。实际选择时需针对确切版本/权重/依赖核查官方许可、商用与隐私限制，记录版本、预处理、费用/硬件和故障行为；不自动下载或上传参考图。

| 类别 | 可考虑的候选/能力 | 不能据此宣称的结果 |
| --- | --- | --- |
| 多模态照片理解/评审 | 当前可用的 Codex 图像理解，或经用户选择的通用多模态模型；用于观察、理由、对比与不确定项 | 单图唯一三维重建、可执行合法参数、猫专用身份识别精度；模型“说像”不是主人批准 |
| 分割 | SAM 2 等通用提示分割候选，或本机人工遮罩 | 自动分出每根毛、真实皮肤表面或无误差 landmark；需人工修正和版本化 |
| 视觉表征/检索 | CLIP/DINOv2 类候选，用于候选聚类、重复检测、辅助诊断 | 可靠的个体熟悉感总分、解剖质量或无背景偏差的身份匹配 |
| 深度/法线建议 | 经验证的通用单目深度/法线候选；仅作多视图一致性假设 | 真实米制尺寸、隐蔽侧面、统一拓扑/骨架/groom；尺度和 domain gap 必须验证 |
| 几何/渲染工具 | 现有 Blender、GLTFLoader/Exporter、严格 inspector、固定本地执行器 | 这些是执行与结构证据，不是照片理解模型，也不会自动形成闭环判断 |

接口保持供应商无关：图像输入由本地引用/摘要和用途授权表达，输出是可解释观察/候选建议；现有 renderer/validator 检查后才执行。图像默认不随日志、公开 PR 或 fixture 上传。选用外部服务、可下载权重或 GPU worker 必须另有明确选择；不把供应商 SDK/CUDA/训练循环放进 Next.js 请求进程。

## 可立即规划的一猫单参数本地试验

**目的：**验证“有依据的照片观察 → 小幅参数修改 → 实际渲染反馈”的收益，不验证照片生成完整猫或写实母模已完成。

1. 在 Mac 的原项目中选一只来源/审查用途明确的现有 Norwegian 母模副本，以及同一只参考猫的获准正面、侧面、斜面照片。至少另留一张独立视图或 session，最后才看。没有获准照片/模型则只交接该清单，不能拿公开 fixture 充当该个体。
2. 核对真正 source/asset revision 与 14 项面部 morph 能力、身体/眼球分拆和 source 不变证据；保存当前完整 appearance/毛参。先实渲染基线并确认 `Shape_headWidth_low/high` 的小幅修改确实影响身体与五官协调，而非只改 JSON。
3. 只选择 `headWidth` 一个参数。冻结 coatType、coatMode、全部毛量/毛长、pose=stand、blink=0、相机、灯光、曝光、seed 和归一化。优先用 source/灰模辅助判断毛体积混淆，最终仍检查原本完整显示模式；不用关闭完整毛层的截图替代最终效果。
4. Codex 看对齐的正面和侧面，给出“更宽/更窄/无法判断”及图中依据；仅当方向有支持时提交一个 ±3 内候选，仍满足 0–100。若基线本已合适或图像证据冲突，不必为了跑流程改值。
5. 通过现有本地任务执行一次；回收 baseline/candidate 的正/侧/斜面原图、模型/参数摘要和结构检查。最多 3 次修改；连续两次无明确收益、任何结构失败或达到预算就停止。
6. 最后看保留视图并请主人比较“哪张更有熟悉感、依据是什么”。输出最佳候选/无改善、仍未知特征与 unsupported 项，以及所有回退记录。原资产、数据库、线上/current 模型不变，不触发 publish。

该试验获得的真图与明确失败同样有价值。成功标准是观察和修改可追溯、真实参数发生预期变化、跨视图没有不可接受的退化、能够诚实停止；不能预先承诺它一定让猫更像，也不能把一次主人偏好外推为全品类模型准确率。
