# 写实猫路线与研究资料核验

> 当前 `/studio/base` 已改用挪威森林猫母模，详见 [当前造型室说明](./CAT-CREATOR.md)。本文保留此前结构猫头的制作与研究记录；其中旧毛发、闭眼等能力不代表当前母模已经具备。


目标是接近 C 图的自然短毛猫，继续保持本地运行、手动捏脸。照片识别不进入当前范围。

## 结论

当前包含三套阶段结果：`/studio` 是旧程序猫，`/studio/base?legacy=1` 是 CC0 虎斑猫的 8 项局部形变，默认 `/studio/base` 已升级为 Blender 加工的结构猫头造型室。新版包含实际眼眶开口、独立眼球/虹膜/瞳孔和上下眼睑，支持三种头型与14项结构控制、部位点选/拖动和数据保存。它已建立结构编辑能力，但尚不能作为大型游戏的美术精度或照片级写实效果验收通过。[新版操作与制作说明](./CAT-CREATOR.md)。

当前决定：停止把程序猫表面精修或虎斑猫小幅形变作为最终捏脸方案。新结构猫头提取原 CC0 形体，移除烘焙眼面、体素重建并加工五官和形状库；不把它描述为手工完成的动画重拓扑。源素材和阶段比较见 [写实猫母模筛选](./CAT-ASSET-SELECTION.md)。继续遵循仅免费、允许修改、本地运行的限制。

当前已围绕眼眶眼睑、口鼻耳廓、眼部材质、毛色短毛和网页预览进行五轮加工，过程与实际画面见[精修记录](./CAT-CREATOR-FIVE-PASSES.md)。稀疏短毛与胡须跟随形体，仍需继续提高毛流、密度和细节质量。Blender 制作形体、拓扑、形状库与毛发，Next.js / React Three Fiber 负责网页编辑与展示；全身骨架和动作尚未制作。

## 目标修正：游戏式猫咪角色创建

用户最新参照是《燕云十六声》的捏脸深度，但对象为猫。这是对编辑体验与可塑性的目标说明，不代表已核实或复用了该游戏的内部技术。拍照识别继续搁置。

现有虎斑猫原型只证明了『参数 → 局部形变 → 保存/导出』通路。它能够产生同一张虎斑脸的小幅变体；不能靠增加滑块或放大现有位移场，直接获得游戏式角色创建能力。后续分别记录两条验收线：一条是形体能捏出多少合理差异，另一条是静态/动态画面是否写实。

后续按以下几项继续深化，结构与美术分别验收，不把局部功能通过包装为整体完成：

1. **可塑猫头母模。** 制作适合变形的连续拓扑，眼眶、鼻梁、胡须垫、嘴角和下颌有实际结构；独立眼球、虹膜/角膜与可包覆的眼睑。首先去掉毛色和毛发，在固定光照下评审正面、侧面与四分之三视角。不能重新用规则球体拼一张脸后宣称高质量母模完成。
2. **结构形状库。** 同一套顶点顺序下制作圆润脸、普通家猫脸和较长楔形脸，支持连续混合。进一步拆出有独立作用的头宽/高/深、额头、颧部、下颌、口鼻凸度、鼻梁、眼眶/眼裂、耳根位置和耳廓倾角。参数数量由真实可区分的结构决定，不作为完成标准。眼睛位置变化必须伴随眼睑与眼眶修正。
3. **游戏式编辑操作。** 点击脸颊、眼睛、鼻口或耳朵时聚焦并高亮该部位；提供有约束的位置、尺寸与角度操作，配合精细滑块、对称编辑、局部重置和调整前后对照。手机采用点选部位和底部精调，提供与拖动等价的按钮/键盘操作。
4. **独立外观与毛发。** 在结构合格后制作不烘焙固定高光的眼部材质；虹膜颜色、瞳孔与光照响应独立于头部毛色。毛色、白斑分布、毛长与毛流跟随同一变形表面，检查形变后接缝、拉伸和毛根漂浮，再进行网页性能优化。

结构编辑的最低验收对象是**一颗能明显改变结构的灰模猫头**。其验收必须同时满足：

- 在完全相同的灰材质、相机和光照下，三种头型正面和侧面均可辨认；中间混合也合理。
- 调整口鼻凸度能改变侧面深度；下颌、脸颊和额头可产生独立的轮廓差异。
- 眼球是独立结构；眼裂、位置和倾角调整后眼皮仍包覆眼球，至少可以验证一次真实闭眼。不能用压扁眼球或拉伸瞳孔贴图替代。
- 组合变化没有明显裂缝和五官穿插；同一形体在网页实时预览与导出再打开后保持一致。
- 灰模通过后再用毛色和毛发评价写实度；功能测试通过不能替代此美术验收。

新版采用独立模型身份 `structural-cat-v2` 和存储键，旧版继续保留，不将旧 JSON 套到新拓扑。结构功能和实际图像检查记录在 `artifacts/cat-creator/`；这不等于最终美术验收。毛色、角膜、稀疏短毛和立体胡须已接入；眼周过渡、完整毛流与动画拓扑仍需精修，全身动作仍未实现。制作过程需要实际的 3D 资产加工与逐视角检查，不能仅靠网页代码或自动生成结果保证大型游戏的美术水准。

## 两项研究对本项目的意义

### NeuralFur

它从经过标定的多视角图像重建动物身体和显式毛发，按身体区域约束毛长和毛流。适合研究毛发重建，不是现成的网页猫咪组件。[项目说明](https://neuralfur.is.tue.mpg.de/)

官方代码要求 CUDA 11.8，并标注 CC BY-NC-SA 4.0、研究用途。本项目没有安装其训练环境，也没有使用其代码或输出资产。[官方仓库](https://github.com/Vanessik/NeuralFur)

### AnimalLift

最值得借鉴的是统一的基础拓扑、UV、骨架、形状参数和绑定在表面的毛发；论文也说明基础形体和毛流模板需要美术制作。这与“先制作好一只基础猫，再让用户修改”的方向一致。[论文第 3、4.6 节](https://arxiv.org/html/2609.09513v1)

当前公开数据包含猫的 OBJ、纹理、毛发张量，不是直接替换现有网页模型的完整骨骼 GLB。数据集许可为 CC BY-NC-ND 4.0，权重为 CC BY-NC 2.0；商业产品复用需要另外解决授权。未将这些资产加入项目。[数据集及许可](https://huggingface.co/datasets/Chunyi99/AnimalLift) · [权重及许可](https://huggingface.co/Chunyi99/AnimalLift)

官方推理安装面向 Linux / NVIDIA CUDA，结果在 Blender 中重建毛发。当前 Mac 上没有执行推理；没有下载整套训练数据。[官方安装与导入说明](https://github.com/Chuny1/AnimalLift)

## 实际制作顺序

1. **中性形体。** 先只做一只成年短毛家猫。制作没有毛发遮挡的基础网格，修准颅骨、颧弓、鼻梁、胡须垫、下巴、肩胛和脚掌。先用灰色材质评审，避免靠毛色掩盖比例问题。
2. **眼睛和面部。** 单独制作眼球、角膜、虹膜、湿润眼缘和上下眼睑。眼睑需要包住眼球，闭眼由眼皮运动完成。鼻翼、鼻孔和嘴角作为实际形体精修。
3. **UV 与毛流。** 展开稳定的 UV，制作毛色、粗糙度与细节贴图；分开底绒和护毛，绘制长度、密度、走向分区。毛根绑定表面三角形及重心坐标，捏脸和动作时跟随同一表面。
4. **捏脸与动作。** 在同一拓扑上制作形状目标，验证单个滑块及组合。单独雕刻趴卧时肩部、腕部、腹底和后腿修正；先确定静止趴卧的轮廓，再制作起卧过程和步态。
5. **网页版本。** 保留高质量 Blender 源文件，另做用于网页的模型和毛发层级。近看保留更多毛发，远处减少细节；根据实测手机帧率和加载时间控制规模。不能把离线渲染结果当成网页实时性能证明。

以上是完整制作路线。当前已实现猫头结构、形状库和初步毛色短毛；手工动画重拓扑、全身骨架、动作与实体手机性能验证仍待完成，不能把路线说明当成高质量全身母模的交付证明。

## 美术验收

- 固定正面、侧面、四分之三角度与面部近景，在相同光照下比较；先看轮廓，再看纹理。
- 眼缘没有明显贴片、缝隙、穿插；闭眼时眼球不缩放、不外露。
- 鼻孔有凹陷，口鼻没有一整块白色球体的观感；胡须有自然弧度与渐细末端。
- 毛发近看有短毛层次，远看轮廓柔和；花纹不呈整齐平行环纹，毛发不变成密集闪烁噪点。
- 趴卧有胸腹支撑，前掌放松、后掌收纳；腕部不分叉，关节不穿出身体。
- 默认形体通过后，再检查最瘦/最胖、最短/最长口鼻和滑块组合。
- 功能测试和美术评审分开记录。当前美术状态：**未达到 C 图写实质量**。
