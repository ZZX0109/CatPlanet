# 程序被毛：恢复覆盖并减少碎毛

当前入口：<http://localhost:3000/studio/base>。

用户明确：程序生成毛丝本身没有问题，应在原来的完整被毛上优化碎毛；关闭毛层导致秃感不符合目标。本轮恢复默认完整程序被毛，原挪威森林猫、342 簇原耳毛、捏脸与动作基础保留，未用私有 Kitten 研究替换正式猫。

## 当前实现

- 原有三角形／重心毛根、总容量和六项毛量／毛长保持。原先逐根随机打散顺序会在远景拆开小毛簇，现改为稳定随机的小簇顺序，任意绘制前缀只可能截断最后一簇。
- 每六根毛保留同一表面上的共享重心中心。收束从毛根的零权重平滑增加，位置与解析导数使用同一函数，毛根不挪动；头部弱收束，长披毛收束有上限，毛尖保留错落。
- 长披毛长度因子上界从 1.38 收至 1.22，局部方向扩散从 .14 收至 .10；胸颈底绒长度因子从 .7 改为 .9，减少底绒与外层长线之间的空档。毛量与用户滑块数值不被重设。
- 默认“完整被毛”；“仅看原模型”用于关闭程序毛进行对照。外观 schema5 将旧 v3/v4 迁移到完整被毛，并保留整份 shape 与 coatType；v5 的明确原模型选择继续保存。迁移不自动覆盖旧本机记录，显式保存时才写新版本。

## 验证与限制

真实修改前完整程序毛的头部／侧面保存在 `artifacts/procedural-groom/before-full-coat/`。后续对照使用同一脸型、六项毛参、相机和灯光；不能仅把 source=0 与恢复毛层比较，当作碎毛质量通过。

整簇顺序 helper 的 41 项 CPU 检查在 `artifacts/groom-patch-order/`。实际网页前后对照、趴卧、保存迁移、手机和构建检查随本轮记录补齐。

底绒不是完全不透明厚壳的同义词。既有程序包含 down／awn／guard 三类细毛，也有独立底层包络。当前仍需要继续评估胸毛是否成帘、尾毛是否成扇、近景是否有亮刺，以及手机负载；恢复覆盖与数值检查不等于已经达到 C 的写实效果。


实际三帧在 `artifacts/procedural-groom/after-full-coat/`：头部和侧面的相机、shape、画布及三区绘制数量与修改前完全一致；另补实际趴卧图。近景仍画 104,000 根程序毛，没有靠减少整层毛量获得“干净”。远景也保留实际三区毛层，WebGL／页面错误为零。类型检查与生产构建通过，默认／模式切换／旧记录／手机触摸键盘的六项回归通过；另两项 v3/v4 存储和导入迁移回归通过。最新汇总见 `artifacts/procedural-groom/current-validation.json`。

独立画面对照确认收束有局部变化，整体改善仍小，胸帘和背颈散线继续存在；不能写成“碎毛已解决”。下一轮继续在完整程序被毛上处理这些问题。


手机竖／横屏实际画布另见 `artifacts/procedural-groom/after-phone/`，两帧均使用完整 groom、三区真实绘制，页面与 WebGL 错误为零。最后还修正了热更新时无保存记录的内存外观迁移，保留未保存 shape；此小修后类型、迁移 CPU 与生产构建再通过，没有重复三维截图。汇总明确区分该检查范围。

## 第二轮：分开处理胸鬃底绒与外披毛

2026-11-05，继续修改完整程序被毛的生成方式。没有减少毛根、关闭毛层或重置用户参数。

先在真实工作室做分层对照：分别临时隐藏头、胸鬃、身体和底层包络，确认胸前长帘主要来自胸鬃；再按实际毛根分类只显示底绒或外披毛，发现密集底绒相对紧凑，较少的外披毛形成了大部分长线轮廓。诊断只在独立捕获页面临时切换，正式页面仍开启完整毛层。证据分别在 `round2-chest-contributors/` 与 `round2-chest-kinds/`。

保留以下修改：

- 毛丝光照使用生成曲线的解析方向，通过压缩的顶点属性传入着色器；缺少该属性的旧几何继续使用原来的计算方式。实际 GPU 绘制已确认使用新方向。这只改善方向连续性，不会把原有折线几何自动变圆。
- 长毛胸鬃单独使用曲线与重力参数，保留底绒和外披毛各自的支撑关系。修改限定在长毛胸鬃，不改共享模板影响其他部位。
- 显式编写的胸鬃毛簇长度／宽度不再被默认值稀释，弱影响区域平滑退回原参数。
- 外披毛后半段沿毛流收回，末端稍贴近底绒，减少悬空长线；毛根、底绒、头部和身体的生成规则保持。

同相机、同脸型、同毛参的实际长毛对照依次在 `round2-analytic-long/`、`round2-ruff-long/`、`round2-style-long/`、最终 `round2-outer-return-long/`。近景仍绘制 104,000 根，三区数量不变。独立画面检查支持保留最后的小幅紧凑化：白胸末端与背颈外撑范围缩小，没有明显新秃区或整齐硬剪边。胸帘、背部和尾巴散线仍在，不能称为写实完成。

最终补拍 `round2-final-short/`、`round2-final-phone/` 与 `round2-final-rest/`，均无页面或 WebGL 错误，完整三区实际绘制，解析方向在 GPU 中启用。短毛头部与本轮仅改光照的短毛基准逐像素相同；侧面仅 15 个像素有最多 1 个色阶差异，不能记为严格逐像素相同。参数、相机、毛量一致。手机横屏与旧基准的画布分辨率相同，但页面内位置不同，不记为完全相同的画布对照。

本轮通过类型检查、最终生产构建、分区毛量／毛长及导出回归（1 项）、材质兼容性 CPU 检查（12 项）和旧几何实际 GPU 检查（5 帧）。上一轮的迁移与默认模式检查记录保留，不伪称本轮全部重跑。当前趴卧图无明显新接触亮带，但尚未穷举所有形变／接触；接地裁剪后的曲线方向仍需专门评估。

汇总见 `artifacts/procedural-groom/round2-validation.json`，有限视觉结论见 `artifacts/procedural-groom/round2-final-QA.md`。下一步仍应针对背颈散线、毛束转折和胸鬃层次继续修改生成方式，并保留完整覆盖。

## 第三轮：先排除显示朝向，再检查曲线采样

增加真实工作室的颈背／尾巴近景与基准 `round3-baseline-long/`，短毛对应 `round3-baseline-short/`。捕获脚本的源码监控补入 groom 文件，保留原有相机视角。

第一项只改变长毛身体的屏幕横向朝向，不改中心线、宽度、毛量、光强、覆盖比例或旧滤波。实际 GPU 确认仅 body 开启候选，但五组同角度画面没有充分改善，背部部分线条更粗亮，尾巴仍有光滑核心与外围弧线，因此拒绝作为默认。两份运行源码已按摘要精确恢复；`round3-restored/` 补拍确认回退。候选源码与材质检查保存在 `round3-raster-candidate-source/`，审查和回退记录为 `round3-raster-QA.md`、`round3-raster-verification.json`。不能把数学上合理的横向改动当作画面质量通过。

下一项针对几何采样。[NeuralFur 的曲率一致性约束](https://arxiv.org/html/2601.12481v1#S3.SS4)用相邻线段的转角描述弯曲；[AnimalLift 的规范空间表示](https://arxiv.org/html/2609.09513v1#S3)保留贴附表面的相对曲线。这里继续保留既有根、尖和连续引导曲线，独立研究同样八段如何分配到转弯位置；没有训练或复现论文网络。

CPU 参考实现先经真实九个生成中心点校验。首次探针将外层网格对象误作底绒判断，参考误差过大，已保存失败记录并修正；有效参考最大误差约 `1.16e-7` 场景单位。有限样本是按区域／毛型比例选的 256 个背部根，每根 65 点，不代表整猫或所有形变。结果在 `round3-body-curve-review/`，CPU 曲率和弦差改善仍需真实画面对照，不能直接记作写实改善。

采样候选已实际接入并验证：匹配样本内的 245 个 body 根拟合三种毛型的共享九点表，限定中性表面向上、非肢尾的长毛身体区域。生成 UV、颜色渐变、位置、切线和 taper 使用同一个实际参数，仍是八段；没有逐帧优化或增加顶点。全容量 7,735 根命中，短毛／头胸／未命中区域逐字节保护，所有身体根尖中心不变；16 项 CPU 接入检查通过。共享表在小样中的转角与弦差改善，但 7/245 根弦差变差，且拟合／回测不是独立样本。

真实五图 `round3-sampling-long/` 仅有细微线段重排，背颈拱丝、网格和尾散线仍在，独立 QA 不支持默认采纳。因此候选也已存档于 `round3-sampling-candidate-source/` 并回退，正式运行代码与第二轮保留版本摘要一致。CPU 接入正确不等于美术改善，见 `round3-sampling-QA.md`、`round3-body-curve-review/production-sampling-validation.json`。

另在独立页面对颈背／尾部仅临时隐藏 `Coat_Undercoat`：`round3-envelope-back/` 与 `round3-envelope-tail/` 各两图，其他毛层均保留。颜色和细节有变化，但光滑核心、外圈弧线仍明显，不能把问题完全归于底层毛壳，更不能把正式默认改成关闭毛层。所有对照无页面／WebGL 错误。后续应继续解决实际曲线造型及毛层体积与光照的衔接，避免反复只调条带朝向或等距采样。

第三轮汇总为 `artifacts/procedural-groom/round3-validation.json`。本轮没有默认视觉升级，短毛与长毛足够真实的目标仍未完成。

## 第四轮：长毛尾部专用造型与实模预览

本轮按用户要求优先展示长毛猫。网页实际站立全身／尾部／趴卧预览在 `round4-long-preview/`，浏览器入口仍是 `/studio/base`，默认完整程序被毛。截图不是生成的参考图。

先检查现有尾毛：当前近景绘制的 tail 类根为 9,173 个。固定 256 根、每根 65 点的 CPU 参考先通过真实九点重建校验（最大约 `1.21e-7` 场景单位），再查原身体与底层毛壳的真实三角面。梳向基本顺着尾骨轴，没有反向根；大部分底绒也形成离体较远的长弧，且尾部原先不使用身体的径向深度分层。另一个问题是单条尾导引的法线只覆盖部分尾周，未覆盖处会回退身体模板。证据见 `round4-tail-review/`、`round4-shape-diagnosis/`。

分两阶段修改，没有增加或删除毛根：A 按中性尾部权重把底绒分布到原冠层内不同深度，上层保留；B 在每根既有的 N/T/B 坐标架中平滑混合尾部专用底绒与过渡毛曲线，减少尾上长拱与尾尖外散。原毛量／毛长控件、八段拓扑、材质和底层壳不改。A 单独的可见收益不足，B 相对 A 有明确外弧收束；完整软毛体积仍未形成。实际分阶段图和独立 QA 为 `round4-tail-depth/`、`round4-tail-shape/` 及对应 QA 文档。

首次 B 同时修改稀疏 guard 毛后，固定趴卧样本的最近面局部负侧风险增加。该方法不是全局 SDF，仍不足以安全采用；因此最终预览已保留全部 guard 的原曲线，只收束底绒与过渡毛。旧 B 风险报告不改写为通过，保存在 `round4-tail-review/candidate-validation.json`；修正后的有限 guard 核验单独记录。

修正后的 `guard-protected-validation.json` 已完成：站／趴全部 5,873 根 guard 的属性、索引与曲线逐字节保持原版；固定尾部小样风险恢复原基线。站立为零，趴卧仍有原来的 2 根、17 个局部负侧点，不能宣称已根除所有接触问题。

最终预览对应源码已通过类型检查与生产构建，三帧实际页面／WebGL 错误为零。分区控制／导出与三基础类型切换的两项回归在 guard 保护前通过，不能记作修改后全套重跑。底层毛壳法线 `.35→.85` 的独立临时对照没有充分可见改善，未纳入正式运行。

平滑尾核、胸帘和身体散线仍明显，当前仅是可查看、可调整的长毛原型，尚未完成写实目标。最新验证状态见 `artifacts/procedural-groom/round4-validation.json`。

## 第五轮：身体接影与远景预算核对

正式保留一项修正：三组程序毛接收场景已有的身体阴影，仍不投射毛发自身阴影。独立页面的全身／胸部 A/B 读回实际 receiveShadow false→true，key shadow map 存在且矩阵、灯光、设计和相机不变；画面变化较小但非空，未见新增黑碎块或明显退化。它不是毛发自影或完整体积散射。证据为 `round5-skin-shadow-*/` 与 `round5-skin-shadow-QA.md`。

有限 CPU 检查还发现：按实际宽度、九点弧长、taper 和 LOD 补宽计算，当前全身视图的身体种植区面积预算约为近背的 68.85%；这不是像素覆盖率或真实毛囊密度测量。223 根底绒小样的峰值均在壳的局部外侧，不支持“底绒大多整根埋在壳里”的解释。记录为 `round5-body-density/`。

随后独立实现光学 LOD 候选：不加宽条带或修改毛根，仅对抽稀后剩余的消光量做补偿。14 帧合成 MRT 测量中，半／四分之一抽样的累计 tau 偏差由约 −29%／−50% 缩至约 −0.6%…+2.1%；零毛及 d=1 原路径通过。但真实六图里的远景毛线也更硬、更显，未形成充分的柔软毛面改善，已拒绝默认并从正式材质恢复原实现。不能用数值预算闭合替代美术验收。

候选与实际 GPU 原始附件保存在 `round5-source/`、`round5-lod-optics-final-gpu/`，图像 QA 为 `round5-optical-QA.md`。可用以下命令在不修改正式材质的情况下重建该失败候选；重建 bundle SHA 与原实测完全一致：

```sh
node scripts/probe-cat-fur-lod-optics.mjs --archived-material=artifacts/procedural-groom/round5-source/cat-fur-material.ts.optical-pilot
```

最终长毛全身／尾部／趴卧与手机全身竖横屏位于 `round5-final-long/`、`round5-final-phone-full/`，均无页面／WebGL 错误，类型与生产构建通过。最新汇总 `round5-validation.json` 明确区分已采用接影和已拒绝的光学候选；长短毛写实目标仍未完成。用户随后提出耳内耳饰毛、耳尖簇毛与脸颊围毛重点，单独进入第六轮。
