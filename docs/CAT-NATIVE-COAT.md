# 原素材被毛对照（历史记录）

本地入口：<http://localhost:3000/studio/base>。

**当前默认已恢复完整程序被毛。** 用户明确允许继续精修程序生成方式，并指出关闭全身毛层造成秃感。以下保留此前原素材模式的审计记录；当前操作、schema5 与程序毛修复见 [最新说明](CAT-PROCEDURAL-GROOM-REPAIR.md)。“仅看原模型”仍作为可选对照，不再作为默认。

用户指出应精细化原模型的毛感，避免在外面不断叠加碎毛。本轮将原素材被毛设为默认，保留原毛发实验供对照，不把移除碎毛当作已经完成写实短毛／长毛。

## 原文件里有什么

下载的 `Norwegianforest.glb` 包含整体被毛形体、毛色、法线与粗糙度贴图，也包含耳内细毛、眉须和胡须等原生细小几何。它们和身体共用网格与材质，没有单独命名为毛发对象；没有独立可逐根梳理的 Hair Curves 或粒子毛发系统，不等于完全没有毛发几何。以前在网页看到的大量外圈细线、胸口丝帘及尾扇，则来自后加的程序毛层。[原始结构审计](../artifacts/native-coat-audit/original-structure.md)。

这里的“没有独立毛发系统”只描述我们实际拿到的 GLB，不能据此断言作者制作时没有用过毛发工具。资料包中的挪威森林猫原件是 GLB；`reviews/norwegian-forest.blend` 是为检查而导入的副本，不是作者提供的原生制作工程。整体网格也已经包含被毛的厚度和轮廓，不能把它当成剃毛后的皮肤，再在外面均匀加一层长毛。

原下载保留不动。原素材的小面片曾在母模制作时被广泛清理，旧代码将它们统称为“胡须片”，但其中也包括几何耳毛。逐组件核对后，已经恢复 342 簇原生耳毛、2,086 个三角面；44 簇口鼻／眉须的 1,562 面仍用现有绑定表面的细须替代。更新了制作副本与网页基础 GLB，更新前版本另行归档。不能把旧制作副本与自身哈希一致，解释为它完整保留了最初下载的毛发几何。

## 使用方式

- 新建默认长毛母模、原素材被毛，继续支持捏脸、站立、趴卧、眨眼、观察与导出。
- 毛发面板的“原素材被毛”保留母模的毛面和轮廓，不显示全身程序毛、实体底绒壳或实验体积层。原素材不具备逐根毛量、毛长编辑能力，因此不显示这些实验滑块。
- “附加毛层（实验）”保留头部、胸颈、身体六个滑块及毛发独览。切回原素材时参数仍保留，可撤销、重做、保存、导入和对照；不把它作为默认写实结果。
- 无毛猫仍使用独立斯芬克斯母模。短毛选项的原素材预览仍沿用挪威森林猫，页面明确说明独立短毛造型尚在精修。

## 实际改动

**默认不准备全身程序毛。** 原素材资源只生成必要的解剖细节，不创建 130,000 根毛的种植缓存和条带数组；三区毛束容量与绘制数量均为零。选择实验模式时才加载完整毛层，切换和取消加载会清理旧资源。

**恢复原有毛流细节。** 原贴图本来具有胸口、脸颊和身体的连贯毛流。之前短毛／长毛预览将法线强度乘了 0.55／0.85；原素材模式恢复相对于作者原值的 1.0，保留加载器处理后的负 Y 方向。粗糙度贴图、颜色、UV 和原始纹理不改。原素材毛面按非金属处理，避免 ORM 贴图的残余金属值影响被毛反光；眼睛材质单独保留。

**显示与导出一致。** 原素材 GLB 导出保留当前脸型和姿态，不夹带隐藏的程序毛束、底绒壳或体积预览。实验模式仍导出完整设定毛量。外观 JSON 保持版本 4，新增 `coatMode: "source" | "groom"`；旧 v3/v4 文件缺少此字段时默认原素材显示，脸型、类型和六项旧毛发参数保持，旧本机记录不会自动改写。

材质调校的原始测量与 11 项 CPU 检查见 `artifacts/native-coat-audit/`；默认真实页面的首轮头部和侧面画面在 `artifacts/native-coat/source-round01/`。它们确认原生毛面在绘制、全身程序毛未绘制，不能据此宣称写实程度合格。

## 原生耳毛恢复

独立 GLB 解析、Blender 组件审计和 CPU 交叉核对共同确认：旧清理条件只按头部权重、组件大小和眼球距离选择，并未真正识别胡须，误删了耳毛。源耳毛可以用其原有耳骨蒙皮权重区分：342 簇耳毛的组件平均耳权重最小约 0.02499，44 簇口鼻／眉须为零。构建时现在先保护耳权重大于 0.01 的候选组件，再清理确定的面部须片；同一来源的 342 簇、2,086 面完整保留。这个阈值是对当前素材验证过的分组规则，不能当作通用动物毛分类算法。

没有重新种植耳毛，也没有新增 Hair Curves。保留这些原毛片的位置、毛色、UV、原蒙皮权重与现有捏脸形变。正式网页 GLB 的身体面数从 25,144 增至 27,230，身体顶点从 13,435 增至 16,189；这 2,754 个新增到导出文件的顶点全部来自原耳毛。两只眼睛的几何不在恢复范围。

同灯 Blender 恢复前后、逐组件清单、正式构建日志和旧输出归档在 `artifacts/native-ear-coat-restoration/`。正式模型摘要为 `bda151cace4e581a2314fe5788bbe27c3fe91cbd589d5ac8f3677d36e481b492`，下载的原 GLB 摘要仍为 `6b027c8d85a79d6c2a06e24939e0faec13b0aee67c84207249018197e4a756f1`。

正式网页的六张实际画布与两张手机整页在 `artifacts/native-coat/restored-ear-final/`：两耳内的原生毛束已恢复；站姿、趴卧及手机竖横屏均实际显示，附加全身体毛容量／绘制量仍为零，没有页面或 WebGL 错误。离线新曲线研究没有接入本次恢复。

恢复后 13 项相关回归通过，0 失败、跳过或不稳定重试，覆盖捏脸、模式切换、保存与导出、手机操作和毛流绑定；类型检查与生产构建通过。独立资产核验确认原有身体的位置、UV、法线、蒙皮权重和 53 个形变目标数据均保持，双眼和内嵌贴图字节保持。恢复的耳毛有真实耳朵大小／倾斜形变，不是贴在画面上的装饰。

验证入口为 `artifacts/native-ear-coat-restoration/final-validation.json`。资产核验中的高精度源坐标变换仍标为 `limited`：原耳毛的 UV、三角连接和蒙皮对应已核对，但用躯干拟合的近似变换不能证明耳毛源坐标在 1e-6 场景单位内精确一致。首版审计把耳上的 Blink 修正应为零、以及 6 个原始耳毛点本就没有耳骨权重误作失败，原样归档并明确更正；未为凑全绿调整模型或放宽坐标精度声明。

## 仍需完成

目前比外围叠加碎毛更干净，但轮廓仍偏贴伏，长毛的柔软蓬松和真正可控毛型仍不足，眼部也还有模型感。后续应沿原有被毛方向精修表面与局部成束轮廓；只有需要实际体积和可控长度的部分，再制作连贯、贴合的立体毛发资产。短毛和长毛都达到参考 C 的目标仍未完成。

具体顺序是先分区修原毛：眼周避免粗硬纹理挤压眼睑，脸颊保留向外后方的过渡，胸口保留向下的束形，尾部保留连续的体积与渐尖。先检查已有毛色、法线和粗糙度的配合，再修整体网格中的成束轮廓。需要重做的局部毛型应替换对应的旧毛面，并处理内外衔接；不能靠增加全身随机细线掩盖问题。毛长、毛量控制须对应这些实际可编辑的资产，不能只把碎毛数量滑块重新开放就宣称原毛已可编辑。

本次方向复查的两张实际网页画面及绘制记录在 `artifacts/native-coat/source-user-steering/`：原生表面实际绘制，附加体毛容量与绘制数量均为零，源码与基础 GLB 摘要保持，无页面或 WebGL 错误。离线 Blender 新毛小样仍是未采用的研究，不是当前网页精修成果。

研究与被撤回实验的历史记录保留在 [毛发写实迭代](./CAT-FUR-REALISM.md) 和 [体积实验](./CAT-FUR-VOLUME.md)，不代表当前默认显示采用那些方案。
