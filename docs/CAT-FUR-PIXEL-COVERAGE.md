# 细毛边缘：从均匀细带到投影覆盖

本轮接续 [第八轮毛发结果](./CAT-FUR-REALISM.md)，保留短毛与长毛的实际三维毛根和曲线，研究网页显示中的细硬边缘。基线完整画面与源码摘要保存在 `artifacts/fur-filter/before/`；这不是重新制作或修饰过的对照图。

## 为什么毛丝会像硬线

第八轮减少了多层毛发的覆盖丢失，透明合成仍是近似；它仍把每根扩宽后的细带赋予横向均匀的覆盖值。几何宽度小于一个像素时，移动一点就可能突然覆盖另一整列片元。这样既会显得硬，也会产生细小闪动。曲线自身的大折角是另一项问题，不能由边缘滤波代替修正。

[Chan、Durand：Fast Prefiltered Lines](https://developer.nvidia.com/gpugems/gpugems2/part-iii-high-quality-rendering/chapter-22-fast-prefiltered-lines) 解释了按像素到线的距离计算预滤波覆盖的方法。本项目按其归一卷积原则实现自己的紧支撑核，不使用整幅画面模糊或亮度补偿。

## 本轮实验方法

设毛丝在屏幕上的代表性半径为 `r`，片元到中心线的垂距为 `d`，单位质量滤波核的累积分布为 `F`：

```text
alpha(d) = F(d+r) - F(d-r)
```

在连续、无限长直线的条件下，积分覆盖面积是 `2r`。实际 GPU 的离散像素、曲线段连接、端点、透视插值和深度遮挡仍要单独测量，不能把这个等式当成所有画面的守恒证明。

当前保留三个内部对照模式：

- `legacy`：第八轮的均匀覆盖与原横向投影。
- `box`：有限毛段与真正的二维方形像素求交集面积。无限直线时可化为垂向为 `n`、宽度 `abs(n.x)` 和 `abs(n.y)` 的两个均匀区间卷积；有限端部不能只用这个一维极限代替。
- `compact`：再卷积宽度为 0.6 像素的横向均匀区间。早期无限直线版本使用解析累积分布；有限毛段版本用三点 Gauss 积分采样移位后的多边形面积，并以更密的独立积分作参考。各权重之和为一，覆盖不使用亮度补偿。

滤波只作用于独立毛发合成路径。着色、灯光、模型参数与预览细节预算分别固定后比较。最终选择以实际面积、白毛亮度、抖动和画面为依据，模式存在不等于已经通过验收。

第一版试验只将一维方核或抛物核按垂距点采样。它的连续积分虽然归一，但不能保证斜向像素栅格在每个亚像素位置都保留面积：实际 16F 读回中，一维方核最坏误差约 41.9%，抛物核约 13.7%，即使各位置的平均误差接近零。该版本没有启用。之后改成先计算真正的二维像素面积，不能用平均值掩盖不利位置的毛量损失。

第二版的无限直线核通过了长直毛检查：各相位面积误差低于 0.8%，白毛能量误差低于 2.4%。短毛和弯毛仍未通过。4 像素直毛斜向显示时漏算约 28.8%，独立 CPU 计算能复现其端部缺失；微卷毛还会因扩大后的共享条带折叠而多算约 43%。这些结果也未作为可用的默认效果交付。

因此后续预览转为独立的有限毛段：`lib/cat-fur-segments.ts` 从当前真实三维曲线读取两端点、半宽、法线和颜色，建立仅在毛发绘制阶段临时加入的实例几何；`lib/cat-fur-segment-material.ts` 对有限梯形与像素方格求交集面积。保守光栅同时覆盖端部和侧面，实际覆盖面积仍由原有限梯形决定。预览不扩大编辑数据或导出模型的宽度。

每段使用平端面，不额外叠加圆端帽。颜色与观察位置按透视关系插值，主体遮挡使用毛段上的实际深度；预览节点在绘制后移除。实例缓存独立拥有其缓冲与材质，按当前可见前缀分配。全量长毛情况下仍会增加 CPU/GPU 存储与像素计算，是否值得启用还要以真实画面及运行开销判断。

## 当前默认与尚未通过的验收

**正式默认仍是 `legacy`。有限毛段的 `box` 和 `compact` 只是内部实验，没有提升为默认效果。** 临时修改材质上的 `coverageFilter` 仅用于实际画面对照，不能将实验模式存在、着色器编译成功或原始缓冲通过，表述为最终显示已经保留毛量与白毛能量。

有限毛段的 6,048 组真实 GPU 检查已经通过端帽、短直毛、弯毛和像素相位的**原始缓冲**门槛，但新增的最终合成读回发现另一项损失：

| 测量层次                                    | `box`     | `compact`  |
| ------------------------------------------- | --------- | ---------- |
| 原始 `Σalpha` 的最坏面积误差                | 0.0613%   | 0.0436%    |
| 原始 `ΣpremultipliedRGB` 的最坏白毛能量误差 | 约 2.20%  | 约 2.20%   |
| 最终 resolve 后的最坏白毛能量偏差           | 约 −20.0% | 约 −16.64% |

数据来自 [真实浮点缓冲及最终合成报告](../artifacts/fur-filter/verification/prefilter.json)，两类指标均保留，不用原始缓冲的较好数字替代最终结果。

问题在于**同一根毛的相邻段被当成不同透明层，分别计算了 `-log(1-alpha)`**。同一像素内，若两段分别占据互不重叠的 0.4 面积，整根毛应覆盖 0.8；当前独立透射率相乘却得到 `1-(1-0.4)^2=0.64`。这不是调亮度、扩大宽度或换滤波核就能正确补回的损失。报告中的 4 像素直毛、半径 0.4 像素、轴向显示案例已复现此问题。

因此，着色器中“有限多边形精确求交”“每个移位多边形保留面积”等说明，只适用于**已验证范围内单段的原始覆盖与预乘颜色贡献**，不代表整根毛或最终多层画面物理守恒。当前 BRDF 和加权透明颜色排序也仍是实时近似；本轮不声称复现完整毛发散射模型。

后续最小修复验证应先用一根毛的两段：先在同一根毛内合并覆盖，互不相交部分求和，交叠处求并集或处理自遮挡，再只计算一次透射贡献；跨不同毛丝才进行层合成。以同一条直毛分别划为 1、2、4、8 段，直接比较最终 resolve 的覆盖与白毛能量，确认显示不再随分段数变暗，再扩展弯曲、遮挡和多毛案例。当前不实现整套逐毛纹理或新的聚合架构，主线先继续真实区域毛型与层次优化。

## 先补稳毛丝方向

按身体表面绑毛不意味着从法线和横向半宽恢复的方向总是可靠。实际第八轮审计中，站姿通常稳定；趴卧身体的非触地长毛仍有少量符号翻转，触地毛的偏差更多。因此增加私有的 `furFilterAxis` 字节标记，将恢复方向校正到生成曲线时已知的解析切线；整根毛触地或接近退化时标为零，退回原预览方式。

这个属性不交换顶点、不改变三维点、半宽、法线、UV 或索引。它与位置更新使用相同的局部更新范围，长短毛切换时随几何一起重建；静态导出不包含它。当前最大容量下，额外 CPU 数组约为短毛 1.30 MB、长毛 2.34 MB，GPU 上传还需要另一份存储。

方向先在模型坐标中恢复，再变换到观察坐标，以支持非均匀模型缩放。随后用齐次投影的导数确定屏幕切线与垂向；片元的 UV 梯度用于估计实际垂距。曲线连接处增加的保守光栅范围只用于提供计算片元，滤波核之外的覆盖仍为零。

## 验证要求

除原来的绑定、导出与合成检查外，新增对照包含：

1. 多种亚像素半径、屏幕角度、斜视、相机旋转和非均匀缩放，读取真实浮点缓冲中的覆盖与白毛能量。
2. 多个均匀的亚像素位置，分别报告平均面积、相邻位置抖动的均值与高分位数，不能只挑有利位置。
3. 多色毛丝的重叠与绘制次序、主体遮挡，以及缺少方向标记和触地标记时的安全退回。
4. 实际短毛、长毛的头部与全身、白胸与灰侧腹，使用同一几何、镜头、灯光和毛量作对照。
5. 记录额外片元成本，区分 CPU 几何开销与真正的渲染开销；手机截图不作为实体手机流畅证明。
6. 同时检查原始缓冲和最终 resolve；同一根毛改变分段数时，最终覆盖与白毛能量也必须通过，不能只验证 `Σalpha` 或 `ΣpremultipliedRGB`。

本轮的边缘采样不会单独完成真实被毛建模。胸颈的长度与方向错落、身体曲线的弧度、底绒与披毛关系，以及小屏幕几何预算仍需继续按实际结果优化。
