# 猫咪多轮精修记录

本轮继续使用现有无毛、短毛、长毛基础，默认仍为正面站姿。本地页面为 <http://localhost:3000/studio/base>，无需账号或云服务。

## 按表格落实的改动

| 优化方向 | 本轮实现 | 检查方法 |
| --- | --- | --- |
| 眼睛与眼睑 | 两套底模增加实际皮肤闭眼形变、按脸型联动的闭眼修正；斯芬克斯采用素材原有眼睑动作烘焙。眼部使用独立光学材质与较小的圆形反光环境，眼球在闭眼时保持原形 | 开眼/闭眼图、中心虹膜射线遮挡、眼球坐标比较；单项端点和叠加参数检查 |
| 口鼻与脸颊 | 连续化脸颊中线权重，保护眼眶；调整口鼻、下颌范围及区域，减少鼻口折叠与下颌牵动后颈。保留原素材基本脸型 | 原生三角形方向与有限数值检查，正面/侧面与混合参数观察；并非完成了全部鼻翼手工雕刻 |
| 毛发层次 | 改善底绒、披毛及少量碎毛的长度与方向变化；长毛保留独立底绒体积层 | 同视角的短毛/长毛与前后轮次实际网页图 |
| 局部毛流 | 分别调整额头、眼周、脸颊、下巴、胸口、腿部与尾巴；腿毛、尾毛参考实际骨骼方向 | 放大、侧面和转头后的实际毛束观察 |
| 胡须与耳朵 | 移除原挪威森林猫的断开卡片胡须面，新增 30 根渐细弯曲管状胡须；耳内毛绑定实际耳腔表面，避免规则白色梳齿。胡须根部与方向跟随头部和皮肤 | 胡须根部、转头方向、耳内有无毛的 A/B 图；头部毛量为零时耳内毛消失，胡须独立保留 |
| 形变质量 | 为闭眼增加脸型修正，修正眼眶、脸颊中线、下颌和后颈的混合权重 | 两套底模各 31 组站姿参数及中性趴卧闭眼检查，另有原生端点/组合三角形诊断；不代表枚举了全部参数组合 |
| 动作与毛发绑定 | 新增站立↔趴卧、微弱骨骼呼吸、偶发眨眼；脚掌在过渡和呼吸中约束地面，毛根随实际皮肤更新，接地毛尖和底绒压低 | 实际皮肤顶点、过渡采样、站姿返回误差、趴卧导出回读；鼠标、触摸和键盘操作 |
| 性能与资产体积 | 按距离减少预览毛束；眨眼和身体动作分开刷新，可见前缀与 GPU 更新量减少；完整导出补齐未显示毛束。标准 glTF 稀疏形变与 gzip 传输，图像不重新编码 | 实际绘制索引数、首/中/末毛根贴合、桌面 CPU 耗时；HTTP 解压后摘要必须与当前 GLB 完全相同 |

## 实际轮次与保留文件

1. **基线与眼周。** 原网页 GLB、脚本和清单备份在 `artifacts/table-refinement/round-00/`。第一轮开眼、闭眼素材渲染在 `round-01/`。
2. **脸部修正与毛发细节。** 皮肤闭眼、脸型修正和形变区域诊断结合，毛发实际图保留在 `groom/round-00` 至 `round-03`。胡须与耳毛采用表面绑定的三维几何。
3. **动作与接触。** 先检查蹲伏与真实趴卧区别，再调整前后肢、身体高度和尾巴。继续修正过渡中脚掌穿地、呼吸时脚掌下沉及接地长毛穿地。
4. **组合形变与性能。** 检查单端点和多参数叠加；优化动作刷新、距离细节与完整导出，最后核对压缩传输及生产构建。

过程中的研究图可能包含未采用结果；最终展示与验收以 `verification/`、最终网页图及最终测试报告为准。

## 使用新增交互

- **闭眼预览**：静态查看真实眼睑闭合，支持继续改变脸型。
- **站立 / 趴卧**：改变实际骨骼姿态；切换结束后镜头重新适配，趴卧中仍可点选脸部和转动观察。
- **呼吸与眨眼**：默认关闭，开启后进行微弱呼吸与间歇眨眼。遵循系统“减少动态效果”，后台页面停止持续绘制。
- 姿态、呼吸与眨眼是临时预览，不写入外观 JSON。基础类型和原有脸部/毛发参数继续保存。
- GLB 导出固定为**当前静态姿态**，包含实际眼睑权重、完整设定毛量和当前毛发；原始素材的其他动画保留在基础制作文件中，不自动附带到当前静态毛发导出。
- 距离简化只影响预览。拉近会补足新可见毛束；导出会更新所有预期毛束的姿态，包括远景未显示的后半部分。

## 构建、资源与代码

- `scripts/refine-foundation-face.py`：实际眼睑、光学材质与脸型闭眼修正。
- `scripts/audit-foundation-face.py`：原生网格形变诊断。
- `lib/cat-creator-motion.ts`：绝对姿态混合、肢体约束、呼吸和眨眼，不累积骨骼偏移。
- `lib/cat-groom-details.ts`：胡须与耳内毛的曲面绑定和方向跟随。
- `lib/norwegian-fur.ts`：局部毛流、距离细节、动作刷新和完整导出。
- `scripts/compact-creator-glb.mjs`：保留原始有限浮点值的 glTF 稀疏存储，生成可逐字节还原的 gzip。
- `app/api/creator-assets/[base]/route.ts`：同一模型 URL 的压缩传输、缓存校验与新鲜度判断；压缩副本未就绪或过期时提供当前原始文件。

```sh
npm run build:cat
npm run build:cat:sphynx
# 上面两个入口在 Blender 生成后自动执行存储优化和 gzip
```

用户提供的原始文件不被覆盖，素材许可状态不因本轮修改而变化。原生 Blender 制作文件含面部形变；本轮网页的程序姿态与实时毛束不等于原生 Blender 毛发/动画工程。

## 验证范围与限制

```sh
npm run typecheck
npx playwright test tests/cat-creator.spec.ts tests/cat-refinement.spec.ts tests/creator-assets.spec.ts
npm run build
```

原编辑、迁移、保存恢复和失败重试也一起回归。新的检查直接读取实际顶点、射线遮挡、绘制数量、GLB 回读及 HTTP 解压结果，不只检查按钮文字。

桌面 Chromium 的一次动作刷新测量中，短毛由约 56.2 ms 的完整重建降到约 18.7 ms 的可见前缀刷新；长毛约 36.4 ms。这是特定本地 CPU 检查，不是实体手机帧率承诺。25% 距离细节样本减少约 75% 的区域毛束绘制，但完整导出数量保持不变。

长毛细边仍有实时渲染颗粒感，眼部光学与鼻翼、嘴线的手工细节仍有提升空间。本轮未达到 C 参考的离线写实质量，也没有完成所有参数组合和实体手机的美术、性能验收。

最终联合回归为 14 项通过；包围范围修正后，眼睑与姿态导出两项另行复检通过。下载数据约为挪威森林猫 16.8 MB、斯芬克斯 16.3 MB，分别还原为约 24.4 MB、29.6 MB 的完整 GLB。压缩前后浮点值和 HTTP 解压摘要均实际核对。
