# 本地离线生活与日记

在已保存的纪念房间中，打开“生活日记”即可开启记录。不需要 AI 密钥。首次开启只记录当前一项活动；再次打开或点击更新时，服务端根据经过的小时补记活动。主人记录、照片及外观不受影响。

## 当前行为

- 时间来自数据库，按北京时间组织日记；每小时一个活动。夜间休息，白天根据固定规则散步、看窗外、梳毛或玩耍。
- 同一账号和小时有稳定的结果，数据库唯一键避免并发探望重复生成。用户不能通过请求指定时间、动作或其他账号。
- 长时间离开每次最多补记最近 168 小时，进度直接推进到当前小时；展示最近 7 个有记录的日期。
- 原始活动日志保留 30 天，访问时及现有定期 cleanup 任务中清理。删除宠物或账号级联删除全部生活数据。
- 日记统一标记 `WORLD_STORY`，界面显示“喵星虚拟故事”。它不会被写入主人填写的真实回忆，也不是 AI 对生前经历的推测。
- 重新读取失败时保留已显示内容并允许重试；未登录或尚未保存宠物时提示先保存。

## 实现与接口

`lib/server/pet-life.ts` 负责服务端规则、事务和补记；`lib/pet-life.ts` 定义来源与日记汇总；`components/PetLifePanel.tsx` 展示日记。数据库在 `db/schema.sql` 中以追加方式迁移，可重复执行 `npm run db:migrate`。

- `POST /api/life/visit`：验证会话与 Origin，按账号限流后补记并返回日记。归属来自 Cookie，不接受 userId 或客户端时钟。
- `GET /api/life`：读取已有生活快照，不启动模拟；尚未开启返回 404。

活动更新与宠物保存/删除使用同一个账号行锁。照片、回忆与日记的数据相互独立，现有数据库备份会包含新增生活表。

## 限制与后续

这是探望时补算的规则模拟，并无常驻后台 Agent，不会主动发送通知。日记中的散步、玩耍等活动暂不驱动三维猫的动画，也没有环境、公共事件、社交或自然语言生成。账号时区当前固定北京时间。

用户已明确暂不接 AI，真实聊天保持未接入；规则日记不代表已接入聊天。正式云部署按用户要求暂缓；真机性能尚未验收。

验证：`npx playwright test tests/pet-life.spec.ts`。用例覆盖数据库补记、幂等与并发、长时间离开上限、日志清理、账号隔离、来源标记、删除级联、界面读取失败重试和手机布局。
